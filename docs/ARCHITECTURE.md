# Архитектур ба шийдвэрүүд

## Урсгал

```
sar_N.xlsx ──ingest──▶ ParsedFile ──classify──▶ ledger ──┬─▶ reports  (орлого-зарлага, мөнгөн урсгал)
                                                         ├─▶ checks   (R1–R9, тулгалт)
                         balances.csv ───────────────────┤
                                                         └─▶ forecast (суурь, хүрээ, сценари)
                                       Analysis (pipeline.py) = дээрх бүгдийн кэш
                                                         │
                     safe_ledger (anonymize) ──▶ tools (6) ──▶ [LLM агент, Sprint 4] ──▶ guardrails
                                                         │
                                                  app/ (Streamlit)
```

## Ledger-ийн баганууд (`schema.Col`)

| Багана | Тайлбар |
|---|---|
| `txn_id` | `YYYY-MM-<мөр>` — хүний засвар (override) энэ түлхүүрээр хадгалагдана |
| `amount` / `direction` / `signed_amount` | Дүн үргэлж эерэг; чиглэлийг ангиллаас тогтооно |
| `activity` | `operating` · `financing` · `internal` · `unclassified` |
| `line` | Нэгдсэн мөр (`sales`, `payroll`, `loan_repayment` …) |
| `class_source` | `rule` · `manual` · (`model` — DM1) |

## Гол шийдвэрүүд

1. **Ашиг зөвхөн `operating` мөрөөр.** Пилотын гар тайлан санхүүгийн урсгалыг ашигт оруулснаас
   улирлын ашиг 15.2 сая биш 4.1 сая ₮ гэж харагдсан. `tests/test_reports.py` үүнийг баталгаажуулна.
2. **Тооцоо нэг газар.** Вэб апп ба агентийн хэрэгслүүд ижил `Analysis` объект ашиглана.
3. **Нууцлал анхдагчаар.** Шалгалтын мессеж ба хэрэгслийн гаралт `safe_ledger`-ээс (харилцагч →
   `CP-###`, тайлбар дахь хувь хүний нэр → `***`, латин галиглал ч мөн). Байгууллагын нэр үлдэнэ.
4. **Faithfulness.** Агентийн текст дэх ₮/сая/% тоо бүрийг бичсэн нарийвчлалын хүлцэлтэйгээр
   хэрэгслийн үр дүнтэй тулгана. Хоёр тооны зөрүүг reference-д санаатайгаар нэмэхгүй
   (санамсаргүй таарц үүсгэдэг) — шаардлагатай зөрүүг хэрэгсэл өөрөө буцаана.

## Файлын формат ба `txn_id`

- **Бэлтгэсэн хүснэгт** (Өдөр, Харилцагч, Дүн, Ангилал, Дэд ангилал, Тайлбар): ангиллаар чиглэл тогтооно.
- **Банкны экспорт** (Гүйлгээний огноо / Дебит / Кредит / Гүйлгээний утга, эсвэл тэмдэгтэй дүн):
  чиглэлийг банкнаас авч, ангиллыг түлхүүр үгээр (`classify_by_keywords`) тогтооно.
  Баганын нэрийн хувилбаруудыг `ingest.COLUMN_ALIASES`-д нэмнэ. Хаан, Голомт банкны бодит
  экспортоор хараахан шалгаагүй.
- `txn_id` = `сар-hash(огноо, дүн, тайлбар, ангилал)`; мөр нэмэгдэх, эрэмбэ өөрчлөгдөхөд
  хүний засвар буруу гүйлгээнд шилжихгүй.

Proposal-д 25 анхааруулга гэж дурдсан нь прототипийн өөр босготой дүрмүүдийн үр дүн. Энд дүрэм
бүрийн босгыг `checks.py`-ийн эхэнд тохируулж болно; DM2-ийн Isolation Forest дараагийн шатанд нэмэгдэнэ.

## Дараагийн алхам

- **Sprint 2–3 (DM1):** `class_source="manual"` засваруудыг шошго болгож TF-IDF + LogReg ангилагч.
- **Sprint 3 (DM2):** Isolation Forest; зориудаар суулгасан 50 алдаагаар recall хэмжих.
- **Sprint 4 (DM4):** LLM tool use (`TOOL_SPECS`) → `RECOMMENDATION_SCHEMA` → `guardrails`.
- **Хадгалалт:** PostgreSQL (хэрэглэгч бүрийн сарын өгөгдөл, таамаг ↔ бодит дүн → BO4 MAPE).
